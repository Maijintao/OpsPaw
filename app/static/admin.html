Agent 介绍

归因 agent

只看不摸

负责回答「为什么坏」。你只说现象——下单失败、页面卡、平台好像挂了，它会先扫一遍 所有接入平台挑出最可疑的服务，再拉指标、链路、日志和调用关系交叉验证，最后给一张 诊断卡：根因落在哪个服务、证据链是什么、属于哪类故障、有多大把握。它的边界是 只看不摸，不改配置、不重启任何东西；数据没接入或某一维采不到时，它会如实说 哪一块看不见，不会硬编一个结论。

修复 agent

白名单动作

负责把确认过的根因修掉。你在诊断卡上点头之后它才动手：先复核现场（容器状态、 日志、功能开关），再选一个动作执行——重启、启动、停止、重建、切换开关、复位全部 开关，执行完再查一遍确认，最后写一张四段回执（现场确认 / 修复过程 / 结果确认 / 它的看法）。它的边界是：只在接了连接器的那台机器上操作，动作仅限白名单那几样； 修不了会停下来说清原因，不会反复硬试。

问答 agent

有据可查

负责日常问答和指路：规范、流程、阈值、处置步骤查知识库，答案带编号出处；问某个 服务现在怎么样，它去查真实的指标、链路和日志；要建工单或提变更，它按流程走确认。 它的边界是只答有据可查的——查不到就说查不到，并给通用建议；写操作只有建工单 一个入口，而且必须你确认才会落库。
